# 11주차 수동 검증용 데이터셋

Streamlit 화면의 CSV 업로드 기능을 검증하기 위한 데이터셋 3종입니다.
모두 `data/`의 시연용 가상 데이터(`data/README_demo_data.md` 참고)로 만들었으며, 실제 기업 자료와 무관합니다.

각 폴더에는 필수 CSV 5종이 들어 있습니다. 폴더 안의 파일 5개를 한꺼번에 업로드 칸에 끌어다 놓으면 됩니다.

| 폴더 | 시나리오 | 구성 | 기대 결과 |
|---|---|---|---|
| `utf8_normal/` | ① 정상 CSV | `data/`의 CSV 5종을 그대로 복사 (UTF-8, BOM 포함) | 업로드 후 분석 결과 화면까지 정상 표시 |
| `cp949_normal/` | ② CP949 CSV | ①과 같은 내용을 CP949로 저장 | 오류 없이 ①과 같은 분석 결과 표시 |
| `missing_column/` | ③ 컬럼 누락 CSV | `hq_financials.csv`에서 필수 컬럼 `total_liabilities`만 제거, 나머지 4개 파일은 ①과 동일 | 파일명과 빠진 컬럼을 알려주는 오류가 표시되고 분석은 실행되지 않음. 앱은 종료되지 않음 |

## 확인 포인트

- **② CP949는 깨진 파일이 아니라 정상 인코딩 파일입니다.** 5개 파일 모두 한글이 앞부분에 있어서 UTF-8로 읽으면 바로 실패하고, CP949 재시도 경로를 반드시 거칩니다.
- **③은 한 파일의 한 컬럼만 뺐습니다.** 오류가 났을 때 원인이 컬럼 검증 단계라는 것을 분명하게 확인하기 위해서입니다.
- 브랜드는 3개(`DEMO_치킨왕` 안정, `DEMO_도자공방` 주의, `DEMO_버거스튜디오` 위험)입니다. 필터를 바꿨을 때 결과가 달라지는지도 이 데이터로 확인할 수 있습니다.

## 사전 확인 결과

데이터셋을 만든 뒤 기존 로더(`load_csv_table`)와 `run_checkup`(`USE_MOCK=true`)으로 먼저 돌려 보았습니다.

- ①과 ②: 둘 다 정상으로 읽혔고, 브랜드 3개 모두 분석이 끝났으며, 두 결과가 완전히 같았습니다.
- ③: `total_liabilities` 컬럼이 없다는 오류로 멈췄습니다.

리나님 업로드 로더(`load_tables_from_uploads`, PR #24)가 main에 들어온 뒤 같은 방식으로 다시 확인했습니다.

- ①과 ②: 정상 적재, 두 결과 동일
- ③: `DataLoadError: hq_financials.csv에 필수 열 'total_liabilities'가 없습니다.`

화면에서의 최종 검증 결과는 `docs/manual_test.md`에 기록합니다.
