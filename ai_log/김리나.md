## [2026-11-12] pipeline 통합 테스트 작성 및 Mock LLM 리팩터링 (담당: 김리나)

### 프롬프트
`franchise_checkup/pipeline.py`의 실제 반환 구조와 예외 조건을 확인한 뒤, 정상 경로 1개와 예외 경로 1개 이상을 포함하는 통합 테스트를 `tests/` 아래에 작성해 달라고 요청했다. 반환값과 키 집합도 함께 검증하도록 했다.

이후 생성된 테스트의 Mock LLM 프롬프트 분기 로직을 검토하고, 프롬프트 유형을 안전하고 명확하게 구분하도록 리팩터링해 달라고 요청했다.

### AI 결과
`tests/test_pipeline.py`를 생성했다.

- 정상 경로 테스트 1개
- 존재하지 않는 브랜드 예외 테스트 1개
- 필수 컬럼 누락 예외 테스트 1개
- 테스트용 5개 CSV 테이블 DataFrame 구성
- LLM 호출을 대체하는 Mock 함수 구성
- 전체 반환 키 집합과 주요 반환값 검증

### 발견한 문제
`run_checkup`은 재무, 정보공개서, 지역 매출, 감사보고서 주석, 계약 조항 등 5개 테이블을 모두 필요로 했다.

또한 하나의 통합 흐름에서 문서 추출 프롬프트와 보고서 생성 프롬프트가 각각 호출되므로, Mock LLM이 프롬프트 유형에 따라 서로 다른 JSON 응답을 반환해야 했다.

초기 Mock LLM은 프롬프트 전체에 `<note_text>` 또는 `<clause_text>`가 포함됐는지만 검사하고 있었다. 입력 데이터에 같은 문자열이 포함되면 프롬프트 유형을 잘못 판단해 잘못된 응답을 반환할 수 있는 문제가 있었다.

### 직접 수정한 내용
- `tests/test_pipeline.py`에 통합 테스트를 작성했다.
- 정상 경로에서 다음 값을 검증했다.
  - 기준연도
  - 재무비율
  - 계약 종료율
  - 지역별 평균 매출
  - 회수 시뮬레이션 결과
  - 보고서 내용
- 정상 경로의 최상위 반환 키 집합과 보고서 키 집합을 검증했다.
- 존재하지 않는 브랜드와 필수 컬럼 누락 시 `PipelineError`가 발생하는지 검증했다.
- 테스트용 Mock LLM을 사용해 실제 외부 LLM 호출은 발생하지 않도록 했다.
- Mock LLM이 프롬프트의 시작 문장으로 보고서·감사보고서·계약 조항 프롬프트를 명확히 구분하도록 리팩터링했다.
- 예상하지 못한 프롬프트가 전달되면 조용히 잘못된 응답을 반환하지 않고 `AssertionError`가 발생하도록 수정했다.
