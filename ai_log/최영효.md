## 1. 교차 리뷰 C 반영: signals.py value_for 중복 제거 (refactor)
- 리뷰 내용: 1조 리뷰 C — calc_financial_ratios와 calc_termination_rate 안에 똑같은 내부 함수 value_for가 중복 정의되어 있음
- 판단: 수용. 두 함수가 숫자 검증 규칙(숫자가 아니거나 NaN이면 None)을 공유하므로 한 곳에서 관리하는 것이 맞다고 판단
- 프롬프트(요약): "1조 교차 리뷰 C(signals.py value_for 중복)를 반영해서, 동작 변경 없이 중복 함수를 하나로 빼는 리팩터링 방법을 단계별로 알려주세요"
- 생성된 코드: 모듈 상단에 `_numeric_or_none(row: dict, key: str) -> int | float | None` 헬퍼를 추가하고, 두 함수 안의 value_for 정의를 삭제한 뒤 호출부를 `_numeric_or_none(fin_row, ...)`, `_numeric_or_none(disc_row, ...)`로 교체
- 문제점:
  1. 코드를 붙여 넣는 과정에서 `total_liabilities = ...` 한 줄만 들여쓰기가 8칸이 되어, 위쪽 `if not isinstance(...): raise` 블록 안으로 들어감. 문법 오류는 아니라서 바로 드러나지 않지만, 정상 입력에서 NameError가 발생할 수 있는 상태였음
  2. 불필요한 빈 줄이 추가되어 리팩터링 diff가 지저분해짐
  3. 전체 테스트 실행 시 test_app.py가 수집 단계에서 실패함(streamlit 미설치 → 설치 후에는 app.py의 import 경로 문제, 리팩터링과 무관)
- 수정:
  1. AI에게 diff 검토를 요청해 들여쓰기 오류를 발견하고 4칸으로 수정
  2. 빈 줄 정리 후 `Select-String ... "value_for"`로 잔여 호출이 없음을 확인
